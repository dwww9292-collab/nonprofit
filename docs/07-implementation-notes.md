## 0. 실제 파일로 검증 완료 (2026-08 추가)

기재부(재정경제부) 지정누계 2개 분기분과 행정안전부 비영리민간단체 등록현황 전국 파일을 실제로

아래 1번은 실물 확보 전에 쓴 내용이며, 방어적 설계가 왜 필요했는지에 대한 기록으로 남긴다.

## 1. (이력) 실제 샘플 파일 부재 — 파서에 미치는 영향

파서 작성 시점에는 실물이 없어 **docs/04의 헤더 별칭 테이블만 근거로** 작성했고, 다음과 같이 방어적으로 만들었다.

- 열 순서에 의존하지 않고 **헤더명으로만** 매핑한다 (테스트: `test_parser_is_column_order_independent`).
- 상단 제목/공백 행이 있어도 최대 15행까지 스캔해 별칭 매칭이 가장 많은 행을 헤더로 잡는다.
- 별칭 완전일치 → 부분포함 순으로 찾으므로 `법인명(한글)`, `소재지 주소` 같은 변형도 흡수한다.
- 필수 헤더(`org_name`)를 못 찾으면 배치를 FAILED로 만들고 **파일에서 읽은 헤더 원문을 error_message에 남긴다.**
  실제 파일이 들어왔을 때 별칭만 추가하면 되도록 하기 위함이다.

**다음 담당자가 할 일:** 실제 파일 2개 분기분을 `samples/`에 넣고 업로드 → 미리보기 화면의
"매핑되지 않은 열" 목록을 확인 → 필요한 별칭을 `app/ingest/base.py`의 `HEADER_ALIASES`에 추가.

## 2. 유사도 중복 임계값 0.9의 실측 동작

docs/01의 4단계(유사도 ≥ 0.9 + 시군구 일치 → 중복의심 표시)를 pg_trgm으로 구현하고 실측했다.

| 비교 | similarity |
|---|---|
| 예시복지재단 vs 예시복지재단 | 1.00 |
| 예시복지재단 vs 예시복지재단재단 | 0.78 |
| 예시복지재단 vs 예시복지재단A | 0.67 |
| 한빛문화협회 vs 한빛문화연합회 | 0.36 |

즉 **0.9는 사실상 "정규화 후 동일한 명칭"만 잡는다.** 정규화가 법인격 접두어·공백·특수문자를 이미
제거하므로, 실제로 이 규칙이 발동하는 경우는 "명칭은 같은데 시도가 달라 3단계 자동병합에 걸리지 않는"
케이스다(예: 서울 중구 / 부산 중구). 오탐이 없다는 점은 장점이지만, 표기가 조금 다른 동일 법인은
못 잡는다. 한국어 조직명에 트라이그램 유사도가 잘 맞지 않는 것이 원인이다.

**권고:** 임계값을 낮추기보다(0.7로 내리면 무관한 단체가 대량으로 걸린다), 2차 고도화에서
"핵심 키워드 토큰 일치 + 주소 동일" 같은 규칙을 추가하는 편이 낫다. 지금은 문서대로 0.9를 유지했다.

## 4. 확정한 판단 (문서에 명시되지 않았던 부분)

- **상태 자동 전이의 우선순위**: 담당자가 수동으로 정한 상태(QUALIFIED/ON_HOLD/LOST)는 자동 전이가
  덮어쓰지 않는다. NEW/ASSIGNED/CONTACTED만 자동 전이 대상이다.
- **기고객 리드**: 생성은 하되 `is_existing_customer=true`, 점수 0 / 등급 D, 목록 기본 필터에서 제외.
  기고객 명단을 지우고 재매칭하면 점수가 정상 복구된다(`retag_existing_customers`).
- **병합 시 신뢰 소스**: `designated_at`과 `asset_size`만 기재부·홈택스 소스에서 덮어쓴다.
  나머지는 "빈 필드만 채움" 원칙 유지.
- **CSV 내보내기**: 엑셀 한글 깨짐 방지를 위해 UTF-8 BOM을 붙인다.
- **수기입력 중복**: 1~3단계에 걸리면 저장을 막고 409로 기존 리드를 알려준다(문서의 "그래도 저장 시
  possible_dup 표시"보다 엄격). 유사도 단계만 걸리면 저장하고 배지를 붙인다.
- **`광주` 지역 판정**: 광역시 표기(광주광역시)일 때만 29로 보고, `경기도 광주시`는 41로 분류한다.

## 6. MVP DoD 대비 상태

docs/06의 완료 기준 전부 충족. 단, 아래 두 가지는 조건부다.

- "samples 파일로 end-to-end 동작": 실제 파일이 없어 **문서 규격대로 생성한 픽스처**로 검증했다.
  실제 파일 확보 후 재검증 필요(1번 항목 참조).
- "docker compose up으로 로컬 전체 기동": compose 파일과 Dockerfile을 작성했으나 **이미지 빌드는
  미검증**이다. 개발 환경에 Docker 데몬이 없어(CLI만 설치) `docker compose build`를 실행할 수 없었다.
  대신 로컬 PostgreSQL + uvicorn + vite 조합으로 전 기능을 검증했다(마이그레이션 적용, 시드, API 33개,
  화면 8개 실브라우저 렌더링). 사내 환경에서 `docker compose up --build`를 한 번 돌려 확인할 것.

## 7. 1차 고도화 진입 시 유의점

크롤러는 `app/ingest/pipeline.py`의 `ingest_rows()`를 그대로 재사용하면 된다. 커넥터는
`RawRow` 리스트만 만들어 넘기면 되고, diff·중복제거·스코어링·raw_records 보존은 이미 공통 경로다.
`BaseFileParser.to_candidate()`와 같은 시그니처로 `to_candidate()`를 제공하면 파일 파서와 동일하게 동작한다.

크롤링 착수 전 소스별 robots.txt/이용약관 검토 결과를 `sources.crawl_allowed`와 `crawl_note`에
기록하는 절차를 먼저 세울 것(설정 화면에서 입력 가능).

### 8.3 실데이터가 드러낸 결함과 수정

문서상으로는 드러나지 않던 문제들이다. 전부 회귀 테스트를 붙였다(`tests/test_ingest.py` 하단).

1. **raw_records에 매핑된 열만 저장하고 있었다.** CLAUDE.md의 "원문 그대로 보존" 위반이며,
   기재부의 `지정기간`·`명칭변경(전)` 같은 열이 통째로 사라져 재처리가 불가능했다.
   → payload에 원본 열 전체를 보존하도록 수정.

2. **여러 시트로 나뉜 파일에서 한 시트만 읽었다.** 행안부 파일은 `중앙`/`시도` 두 시트라
   89%(12,563행)를 잃고 있었다. → `merge_all_sheets` 옵션 추가.

3. **같은 배치 안의 중복 행이 유니크 제약을 깼다.** 세션이 `autoflush=False`라
   `lead_sources` 존재 확인 SELECT가 미flush 삽입을 못 봐 같은 (lead, source, batch)가 두 번
   INSERT됐다. 한 파일에 같은 단체가 여러 행 있을 때(기재부 27건, 행안부 52건) 터졌다.
   → `ON CONFLICT DO NOTHING`으로 변경.

4. **지역 미상이 병합을 막았다 — 가장 영향이 컸다.** 기재부 파일에는 주소 열이 아예 없어
   전 건이 region 99인데, 중복 판정 3단계가 지역 일치를 요구해 같은 단체가 소스별로 갈라졌다.
   실측 **1,314개 단체가 2,650건의 중복 리드**로 존재했다.
   → '99'는 "정보 없음"이므로 불일치로 취급하지 않도록 수정. 병합 시에도 '99'를 빈 값으로 보고
   실제 지역으로 채운다. 결과적으로 중복 1,316건이 사라지고 병합이 1,342건으로 늘었다.

5. **정규화가 법인격을 지워 별개 법인을 합칠 뻔했다.** `(사)함양군장학회`와 `(재)함양군장학회`는
   정규화하면 같은 키가 된다. → 양쪽 명칭에 법인격이 **명시돼 있고 서로 다를 때만** 병합을 막는다
   (한쪽에 표기가 없으면 같은 법인의 다른 표기로 보고 병합). 소스 기본값(ORG_NPO_GROUP)은
   판단 근거로 쓰지 않는다.

6. **주소가 시군구부터 시작하는 행이 19%였다.** "사상구 모라동 421"처럼 시도명이 없어
   지역을 못 잡았다. → `등록기관`(관할 지자체)으로 보정. 19% → **0.01%(2건)**.
   덤으로 우편번호 접두("(301-841)대전 중구")와 특례시 표기(수원·화성·용인·고양·창원)를 처리했다.

7. **행안부 `유형` 열을 버리고 있었다.** 사단법인/재단법인이 명시된 행이 1,016건 있는데
   일괄 ORG_NPO_GROUP으로 넣고 있었다(유형 배점 12점 vs 18~20점).
   → 유형이 명시된 경우 그 값을 쓰고, 비어 있을 때만 ORG_NPO_GROUP.

8. **기재부 파일의 시트명이 "지정누계"가 아니었다.** 실제로는 "2026.2분기 기준".
   단일 시트라 동작은 했지만 키워드를 실물에 맞게 넓혔다.

### 8.4 남은 판단 사항 (사용자 결정 필요)

**기재부 단독 리드는 A등급이 될 수 없다.** 주소가 없어 지역 배점이 REGION.UNKNOWN(6점)으로
고정되기 때문이다. 최대 점수는 30(신규지정) + 20(재단) + 8(자산미상) + 6(지역미상) + 15(신선도) = 79점 → B등급.
현재 A등급 44건은 모두 행안부 파일과 병합돼 주소가 채워진 건이다.

즉 **행안부 파일을 반드시 함께 적재해야 스코어링이 제대로 작동한다.** 기재부만 넣으면
"즉시 배정 필요" 위젯이 영원히 비어 있게 된다. samples/README에 적재 순서를 명시해뒀다.

이대로 둘지, 아니면 (a) 관할 지방국세청으로 지역을 추정할지(부정확 — 중부청은 경기·강원·충북에 걸침),
(b) REGION.UNKNOWN 배점을 올릴지, (c) 등급 컷을 조정할지는 영업 정책 판단이라 열어둔다.
